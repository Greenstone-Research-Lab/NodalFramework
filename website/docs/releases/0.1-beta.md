# 0.1 beta release notes

The 0.1 beta line is the first release candidate intended for hands-on use
outside the repository. It keeps every public package on one version and treats
provider differences as explicit capabilities rather than silent fallbacks.

## Package set

- `Nodal.Core`
- `Nodal.Migrations`
- `Nodal.Neo4j`
- `Nodal.TigerGraph`
- `Nodal.Analytics`
- `Nodal.Tool`
- `Nodal.Import`
- `Nodal.Import.Csv`
- `Nodal.Import.Relational`

`Nodal.PatternRecognition` is not part of the beta package set. Public analytics
remain limited to provider-neutral contracts and integrations executed by a
configured graph platform.

## Beta capabilities

- Strongly typed node and relation metadata, queries, traversals, projections,
  aggregates, change tracking, and unit-of-work mutation planning.
- Neo4j and TigerGraph providers with independently declared and verified
  capability profiles.
- Portable migration intent, deterministic schema planning, durable history,
  immutable bundles, rollback safety, and CLI deployment workflows.
- Provider-executed analytics integration with explicit Neo4j GDS and
  TigerGraph installed-query requirements.
- Bounded canonical analytics observations with typed identities, immutable
  projections, preserved relationship direction, and fail-fast endpoint
  validation.
- Bounded CSV import, deterministic mapping and dry-run evidence.
- SQL Server and PostgreSQL metadata discovery, bounded relational reads, and
  reviewable relational interaction models with JSON, GraphML, GEXF, and DOT
  projections.

## Upgrade from alpha

1. Update every explicit Nodal package to the same beta version. Do not mix
   alpha and beta packages.
2. Remove any reference to the discontinued `Nodal.PatternRecognition`
   package. Provider-executed analytics use `Nodal.Analytics`; proprietary
   analytics are not distributed from this repository.
3. Rebuild migration bundles with the beta tool when deterministic release
   evidence must identify the beta framework version. Previously applied
   migration history remains subject to its recorded checksum and must not be
   rewritten.
4. Review the provider [compatibility matrix](../providers/compatibility.md)
   and [query parity guide](../providers/query-parity.md) before switching
   providers.
5. Run a dry-run for every import or migration before approving writes.

## Release verification

Every beta publication runs formatting, Release build, unit and architecture
tests, a 95% per-package line-coverage gate, NuGet API compatibility checks,
package-content validation, dependency auditing, and a clean-room consumer.
The release artifact also contains exact commit evidence, the capability
JSON-LD graph, an SPDX SBOM, symbol packages, and GitHub package provenance
attestations.

Neo4j 5.26 Community and TigerGraph 4.2.4 Community are the live provider
baselines for this beta line. Other versions are not certified merely because
their vendor clients can connect.

## Stability boundary

Beta means that compatibility is now reviewed and reported; it does not promise
that every public API is permanently frozen. Any required pre-1.0 breaking
change will be documented in release notes and reflected in the package API
baseline. Provider-native behavior that cannot satisfy the portable contract
continues to fail before transport or remains an explicitly named provider
extension.
